# 存 JD 全文（反转 SPEC §2 / §6.2 的非目标）

SPEC §2 把「不存 JD 全文」写成了明确非目标，§6.2 给了两条理由：仓库每天膨胀、
以及把整篇第三方内容复制进一个**公开**仓库的版权边界不清。本 ADR 记录为什么要
反转它、以及反转时用什么手段把当初那两条理由的代价压住。

## 背景

页面上的「简介」原本只有 JobsDB 的 `teaser`（实测平均 85 字符，两行就被截断），
LinkedIn 更是一条都没有 —— 搜索卡片本身不带任何 JD 文本。用户要求看到完整介绍，
并且搜索要覆盖全文。

一件事在动工前就查清了，它决定了这个功能的形状：

| 源 | 详情页全文 | 依据 |
|---|---|---|
| LinkedIn | ✅ 拿得到 | `jobs-guest/jobs/api/jobPosting/<id>` 经 curl 返回 200，正文在 `show-more-less-html__markup` 里（实测一条 2949 字符） |
| JobsDB | ❌ 拿不到 | `/job/<id>` 对 curl、undici、第三方代理一律回 **Cloudflare 挑战 403**；搜索 API 只给 `teaser` + `bulletPoints`；GraphQL 网关的 `jobDetails(id:)` 类型存在但**不暴露任何正文字段**（逐个字段名探测过） |

## 决定

**两源都实现详情抓取，取不到就降级**；全文与摘要并存，页面上摘要照旧、多一个
「展开全文」按钮；搜索的干草堆从「标题 + 公司」扩到「标题 + 公司 + 全文」。

四条配套约束：

1. **全文上限 4000 字符**（`config.json` 的 `site.descriptionLength`）。这是为了
   把 §6.2 第一条理由的代价压住 —— 见下面的后果分析。
2. **只补主库里还没有全文的记录**。每天补新增的那十几条，而不是把主库整个重抓：
   请求量不随主库增长，ADR 0001 的「低频」承诺因此仍然成立。
3. **失败一律降级**。取不到全文只是少一个展开按钮，不改变抓取成败，也不参与
   下架判定。
4. **403 / 451 立刻短路**。那是 Cloudflare 挑战 / 法律拦截，同一源后续每一条都
   必然同样失败。JobsDB 因此每次扫描只浪费一个请求就收手，`meta.descriptions.blocked`
   里如实记下。

## 考虑过的替代方案

- **只在点击时由浏览器现拉** —— 否决。跨域被 CORS 挡住，绕过去要么上代理、
  要么把请求打回对方站点；静态站点的立身之本就是没有服务端。
- **只做 LinkedIn（JobsDB 保持原样）** —— 否决。功能会按源分裂成两种表现，
  而用户看到的是一张列表，不是两张。
- **为了 JobsDB 上浏览器渲染（Playwright / 渲染代理）** —— 否决。理由同 ADR 0003：
  为一条路径把「零 npm 依赖、无构建步骤」和「不把请求转给第三方」一起赔进去，
  代价大于收益。等 Cloudflare 放行或换出口 IP 能通时，现有代码直接就能工作。
- **换更长但仍截断的摘要（比如 1000 字符）** —— 否决。用户要的是完整介绍，
  而「更长的摘要」既没满足需求，又照样要付出抓详情页的请求代价。

## 后果

1. **仓库体积**：全文按 4000 字符封顶，一条大约 4KB。按每天新增十几条、主库累积
   估算，约 2 万条时接近 80MB。SPEC §9 已有的「到 ~1 万条时按年分片」因此从「可选」
   变成「该做」；在触发之前，`site.descriptionLength` 是现成的旋钮。
2. **版权边界**：`docs/` 是 GitHub Pages 的公开根目录，全文因此是公开的。保留
   SPEC §6.2 的原意 —— 页脚明示「版权归原站点，此处只做索引与跳转」，并且每条都
   带可点的原始职位页链接。若原站点主张删除，删 `data/jobs.json` 里对应记录即可。
3. **LinkedIn 的请求量**：ADR 0001 把访问限定在「低频、个人使用」。详情抓取让
   首次运行多出约 20 个请求、此后每天十来个（只补新职位），量级仍是个人使用。
   这个前提变了的话，正确做法是 `enabled: false`，而不是继续加码。
4. **JobsDB 的全文字段长期为空**。这不是 bug，是现状；`meta.descriptions.blocked`
   与 README 的「已知限制」都写明，免得后来者把它当成解析器写错了。
